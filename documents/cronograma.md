## 5. Dependències entre activitats

Les activitats s'organitzaran seguint un ordre lògic per a facilitar el desenvolupament del projecte.

- **#1:** estableix l'organització general del servei Help Desk.
- **#2:** permet identificar i organitzar els equips i perifèrics.
- **#3:** defineix com se sol·licita el material necessari.
- **#4:** estableix el procediment de recepció i reparació d'equips.
- **#5:** utilitza l'organització del servei per a classificar les incidències.
- **#6:** defineix el registre i seguiment de les peticions dels clients.
- **#7:** organitza el control dels components i materials disponibles.
- **#8:** documenta el procediment per a resoldre problemes de programari.
- **#9:** documenta el diagnòstic dels problemes de connectivitat.
- **#10:** recopila i revisa les fitxes de les activitats.

Les activitats #5, #6 i #7 necessiten la informació dels procediments inicials. Les activitats #8 i #9 utilitzen els criteris de classificació i registre per a documentar les incidències tècniques.

## 6. Seguiment del projecte

El seguiment es realitzarà mitjançant GitHub Projects, utilitzant un tauler Kanban amb quatre columnes:

- Per fer.
- En progrés.
- En revisió.

Cada incidència tindrà una data d'inici i una data de finalització.

## 8. Control i revisió

Durant el desenvolupament del projecte es revisarà periòdicament el cronograma per a comprovar el progrés de les activitats.

Si es produeix algun retard o canvi en la planificació, s'actualitzaran les dates corresponents en GitHub Projects i en la documentació.Es crearà una vista Roadmap en GitHub Projects que utilitzarà els camps Data d'inici i Data de fi.

Aquesta vista permetrà visualitzar les activitats en una línia temporal i comprovar que coincideixen amb el diagrama de Gantt.

Les tasques es mouran entre les columnes segons el seu estat real.
